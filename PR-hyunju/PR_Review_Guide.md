# 🚀 Pull Request(PR) 작성하기:리뷰어가 참여하여 PR폴더를 만들기
> **목적:** 협업 프로젝트에서 리뷰어의 효율적인 검토를 돕고, 생산적인 코드 리뷰 문화를 구축하기 위한 PR 폴더 및 문서 작성 안내입니다.

오픈소스 및 팀 프로젝트에서 **Pull Request(PR)**는 단순히 코드를 병합하는 과정을 넘어, 팀원들과 기술적으로 소통하는 가장 중요한 창구입니다. 리뷰어가 변경 사항을 신속하고 정확하게 파악할 수 있도록 아래 가이드를 준수하여 PR을 작성해 주시기 바랍니다.

---

## 📁 1. 권장하는 프로젝트 디렉터리 구조
프로젝트의 루트(Root) 디렉터리가 난잡해지지 않도록, 본인의 작업 내용과 관련된 문서 및 리뷰 기록은 지정된 폴더 내에서 관리합니다.

* `docs/` : 프로젝트 관련 기획서, API 명세서, 아키텍처 설계 등 문서화 파일 관리
* `PR-현주/` : 본인의 PR 제출 이력, 개인 리서치 노트 및 리뷰 피드백 아카이빙 폴더
  * *파일명 예시:* `PR_Review_Guide.md`, `YYYYMMDD_feature_log.md`

```
EGOV-VSCODE2026/
├── src/                          # 프로젝트 소스 코드
├── docs/                         # 전역 기획서 및 API 명세서
└── PR-hyunju/                    # 본인의 고유 PR/리뷰 아카이빙 폴더
    ├── PR_Review_Guide.md        # [Present] 본 가이드 문서
    └── 20260529_feature_log.md   # 작업 단위별 히스토리 및 리서치 노트   

```
* PR-[본인ID]/ : 본인의 기여 내역, 개인 리서치 노트, 핵심 피드백 요약본을 보관하는 독립된 작업 공간입니다.

* 통일된 네이밍 규칙: 폴더 및 파일명 생성 시 공백 대신 케밥 케이스(-) 또는 스네이크 케이스(_)를 사용하여 CLI 환경에서의 접근성을 높입니다.
---

## 📝 2. Pull Request 본문 작성 템플릿 (Checklist)
PR을 생성할 때 본문 파트에 아래 템플릿 양식을 활용하여 작성하면, 리뷰어의 코드 파악 시간을 획기적으로 줄일 수 있습니다.

### 🔍 1. 변경 사항 요약 (What is this PR?)
- [ ] 이번 PR에서 구현한 핵심 기능 및 수정된 코드의 범위를 명확히 기술했나요?
- [ ] 영향을 받는 모듈이나 UI 컴포넌트가 있다면 언급해 주세요.

### 🤔 2. 작업 배경 및 목적 (Why is this change required?)
- [ ] 이 작업을 수행하게 된 배경(이슈 레포트, 기능 요구사항 등)을 기술했나요?
- [ ] 기술적인 의사결정(특정 라이브러리 선택 이유, 알고리즘 채택 근거 등)이 있다면 공유해 주세요.

### 📸 3. 테스트 및 검증 방법 (How has this been tested?)
- [ ] 로컬 환경에서 정상 작동함을 확인한 테스트 시나리오를 적었나요?
- [ ] UI 변경 사항이 있는 경우, 전/후 비교 스크린샷이나 GIF 화면을 첨부해 주세요.

---

## 🤝 3. 생산적인 코드 리뷰를 위한 소통 매너
1. **건설적인 비판과 열린 수용:** 코드 리뷰는 코드의 품질을 향상하기 위한 유기적인 과정일 뿐, 작성자에 대한 개인적 평가가 아닙니다. 리뷰어의 피드백을 존중하되, 의도가 다를 경우 논리적 근거(공식 문서, 벤치마크 결과 등)를 바탕으로 토론하세요.
2. **명확하고 구체적인 질문:** 의견을 남길 때는 무조건적인 수정 요구보다 "이 방식을 적용하면 메모리 효율 측면에서 더 유리할 것 같은데 어떻게 생각하시나요?"와 같이 근거를 함께 제시해 주세요.
3. **리뷰어(Reviewers)및 담당자(Assignees)명시:** PR 생성 후 우측의 `Reviewers`와 `Assignees`를 정확히 지정하여 협업 프로세스가 정체되지 않도록 관리합니다.
4.  **P-Level기반의 리뷰 피드백 활용:** 피드백의 경중을 나누어 소통하면 오해를 줄일 수 있습니다. (예: P1: 꼭 고쳐주세요, P2: 제안합니다, P3: 단순 질문이나 사소한 의견입니다)
